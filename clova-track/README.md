# super-clova (클로바 트랙)

> **병합 안내 (2026-09-23):** 이 폴더는 원래 독립 프로젝트 `scratch/super-clova`였으나, my-talking-claw의 **음성 프론트엔드 대체 트랙**으로 수렴함이 밝혀져 이곳(`my-talking-claw/clova-track/`)으로 병합됐다. 코드네임은 super-clova 유지. **현재 이 트랙은 대기 상태** — my-talking-claw 본선은 ReSpeaker Lite(USB-RPi) 경로로 진행하고, 클로바는 본선이 성숙한 뒤 착수하는 **병렬 업그레이드 트랙**이다(로드맵 2·3단계). 왜 이렇게 갈렸는지·이 트랙이 본선과 어떻게 맞물리는지는 상위 [../음성IO-로드맵.md](../음성IO-로드맵.md)와 [MERGE.md](MERGE.md) 참조.

네이버 클로바 스피커를 리버스 엔지니어링·개조해, 낮은 응답 품질을 **자체 STT·LLM·TTS 스택**으로 대체하는 프로젝트. 목표는 "슈퍼클로바" — 어떤 질문이든 내 추론 엔진이 답하고 자연스러운 음성으로 응답.

## 왜 이 프로젝트인가

응답 품질이 낮은 근본 원인은 **네이버가 클로바 사업을 철수 중**이라 서버가 방치·축소되고 있기 때문(→ [조사결과.md](조사결과.md)). 그러므로 "네이버 서버를 잘 쓰는" 방향이 아니라 **네이버 의존을 끊어내는** 방향이 정답.

## 핵심 발견 (TL;DR)

- 클로바 확장 플랫폼(CEK/CIC 개발자 콘솔)은 사실상 EOL — **공식 확장 경로(C)는 폐기**.
- **클로바 기기는 안드로이드 머신** (웨이브 = Qualcomm APQ8009 = 스냅드래곤 210). → 네트워크 후킹(A)과 하드웨어 이식(B)이 **하나의 "안드로이드 리버싱" 경로로 통합**되고 훨씬 쉬워짐.
- 결정: **기기를 루팅해 발판을 확보한 뒤, 내 어시스턴트를 기기에 직접 올린다(리퍼포즈)**. 순정 UX가 필요하면 앱 후킹(Frida+MITM)을 대안으로. (→ [경로분석.md](경로분석.md))

## 상태

- 조사: **완료**
- 경로 결정: **완료** (안드로이드/임베디드 리버싱 → 리퍼포즈 or 앱·백엔드 후킹)
- 기기 확정: **클로바 프렌즈(브라운)**. `adb devices` **미인식**(USB 전원 전용 추정).
- **막힌 지점: SoC 미상.** 웨이브=스냅210이지만 프렌즈는 SoC 공개 자료 전무 → 어떤 덤프·루팅·리퍼포즈 방식이 가능한지가 SoC에 따라 갈림. **분해해 칩을 읽어야 확정.**
- 다음: **프렌즈 SoC 식별** — [발판확보-런북.md](발판확보-런북.md) 단계 1.5(USB 지문)·단계 4(분해 후 칩 판독).

## 두 트랙

- **비파괴(네트워크) 트랙** — 기기를 열지 않고 공유기단에서 정찰. 싸고 안전하며 운 좋으면 평문 OTA로 비파괴 발판 확보. **먼저 시도.** → [비파괴-네트워크경로.md](비파괴-네트워크경로.md)
- **분해(하드웨어) 트랙** — SoC를 손으로 읽고 UART/BootROM으로 발판 확보. 신뢰 가능한 폴백. → [발판확보-런북.md](발판확보-런북.md)
