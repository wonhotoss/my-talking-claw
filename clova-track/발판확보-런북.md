# 발판확보 런북

기기에서 코드 실행/펌웨어 접근을 얻는 손작업 절차. 쉬운 문부터 두드리고, 각 단계의 **판정 기준**에 따라 다음으로 분기한다. 모델·펌웨어에 따라 달라지므로, 막히면 관찰 결과를 기록하고 다음 단계로.

> ⚠️ 본인 소유 기기의 개인 용도 상호운용. 분해·EDL·리플래시는 **벽돌(brick) 위험**이 있으니, 진행 전 각 파티션 덤프를 먼저 확보하고(단계 3) 원본 펌웨어를 백업한다.

## 준비물

- PC (Windows/Linux). Windows면 Qualcomm 드라이버 이슈로 **Linux(또는 WSL2 usbipd)** 권장.
- USB 케이블 (데이터 전송용 — 충전 전용 케이블 주의).
- **USB-TTL 시리얼 어댑터** (3.3V, CP2102/FT232 등) — UART 콘솔용.
- 분해 공구 (스퍼저, 정밀 십자, 헤라), 멀티미터 (UART 핀 판별용), 필요시 인두.
- 소프트웨어: `platform-tools`(adb/fastboot), [`bkerler/edl`](https://github.com/bkerler/edl), `binwalk`, `simg2img`, `frida`/`frida-tools`, `mitmproxy`. (설치는 [부록](#부록-툴-설치) 참조)

> **확정 모델: 클로바 프렌즈(브라운)** — 2017-12 출시, 웨이브의 후속 소형기. **웨이브의 스냅드래곤 210 가정은 프렌즈에 적용되지 않는다.** 프렌즈 SoC는 공개 자료 전무(국내/일본 전용 → 미 FCC 없음, 위키·나무위키·국내 분해 블로그 모두 내부 미기재). → **손으로 열어 칩을 읽는 것이 SoC 확정의 유일한 길.**

## 단계 0 — 모델·SoC 식별 ⬜

- 바닥 라벨의 **모델코드/KC인증번호/제조사** 기록.
- **adb 결과: 미인식 확인(2026-08-15)** → USB(마이크로) 포트는 **전원 전용** 또는 adb 비활성 추정. 쉬운 adb 문은 닫힘 → 단계 1.5(BootROM 지문)·단계 3(UART)·단계 4(분해 후 칩 판독)로.

### 단계 1.5 — USB BootROM 지문 (분해 전 비파괴 시도) ⬜

전원 인가/버튼 홀드 상태로 USB를 PC에 꽂고 **어떤 VID:PID로 열거되는지** 관찰(`lsusb` / 장치관리자). SoC 계열이 드러난다:

| VID:PID | SoC 계열 | 덤프·루팅 툴 |
|---|---|---|
| `05c6:9008` | Qualcomm (EDL) | bkerler/edl (Firehose) |
| `0e8d:0003` / `0e8d:2000` | MediaTek (BootROM/Preloader) | mtkclient, SP Flash Tool |
| `1b8e:c003` | Amlogic | aml-flash / USB Burning Tool |
| `2207:xxxx` | Rockchip (MaskROM) | rkflashtool / rkdeveloptool |
| `10d6:xxxx` | Actions Semi | actions tools |

- **뭔가 열거되면**: 해당 계열 툴로 단계 4(덤프)로 직행 — 분해 없이도 진도 가능.
- **아무것도 안 열거되면**(전원만 먹음): USB가 진짜 전원 전용 → 단계 4(분해)로. BootROM 진입은 보통 부팅 시 특정 버튼 홀드 또는 플래시 DAT 핀 단락이 필요하니, 분해 후 재시도.

> 프렌즈처럼 저가·소형기는 마이크 어레이 + AEC를 돌리는 스마트오디오 SoC(예: MediaTek MT8516, Amlogic A113 계열 등)일 가능성이 있으나 **추측일 뿐**, 칩 마킹으로 확정할 것. OS가 안드로이드인지 경량 리눅스인지도 이때 판가름 → 엔드스테이트(1)리퍼포즈의 구현 방식이 결정됨(APK 설치 vs 유저스페이스 바이너리 교체).

## 단계 1 — 물리 인터페이스 정찰 ⬜

- 외부 포트 확인: USB(마이크로/USB-C), 3.5mm, 전원잭. USB가 **데이터 연결**인지 충전 전용인지 확인.
- (선택) 분해해 기판의 **테스트 포인트/헤더** 확인: UART(TX/RX/GND), USB, EDL 진입용 test point.

## 단계 2 — adb over USB (가장 쉬운 문) ⬜

```bash
adb devices
adb shell getprop ro.product.model   # 모델 확인
adb shell getprop ro.build.version.release  # 안드로이드 버전
```

- **잡히면**: 발판 거의 확보. `adb shell`에서 사용자권한 셸 확보 → 루팅/앱 사이드로딩(단계 5)으로. 시스템 앱 제거는 루팅 없이 `pm uninstall --user 0`로도 일부 가능.
- **안 잡히면**: USB 디버깅이 꺼졌거나 포트가 충전 전용. 기기 설정 UI가 있으면(데스크 등) 개발자옵션 시도. 없으면 단계 3(UART)으로.

## 단계 3 — UART 시리얼 콘솔 ⬜

- 기판에서 UART 3핀 추정(TX/RX/GND). 멀티미터로 GND(0V)·TX(부팅 시 3.3V 근처 토글) 판별.
- USB-TTL 연결(기기TX→어댑터RX, 기기RX→어댑터TX, GND 공통), 전원 인가 후:

```bash
# Linux
screen /dev/ttyUSB0 115200    # 안 되면 921600 등 시도
```

- **부트로그/셸 확보 시**: 부트로더 종류(LK/aboot), `fastboot` 진입 가능 여부, 루트 셸 여부 확인. → 단계 5.
- 콘솔이 잠겨 있거나 로그만 나오면 → 단계 4(EDL).

## 단계 4 — 펌웨어 덤프 (SoC별) ⬜

> SoC 계열에 맞는 툴 사용(단계 1.5 표). 아래는 **Qualcomm(EDL) 예시**. MediaTek이면 `mtkclient`(`mtk r ...`), Amlogic이면 USB Burning Tool/aml-flash, Rockchip이면 `rkdeveloptool`로 파티션 리드 — 절차 구조는 동일(전체 파티션 read → 언팩 → rootfs 분석).

- EDL 진입: `adb reboot edl`(가능 시) 또는 부트로더 커맨드, 또는 기판 **EDL test point 단락** 후 전원.
- PC에서 `Qualcomm HS-USB QDLoader 9008` 인식 확인.
- 스냅210(MSM8909/APQ8009)용 **firehose 로더** 확보 후 파티션 덤프:

```bash
# bkerler/edl 예시
edl --loader=<snapdragon210_firehose.mbn> printgpt
edl --loader=<snapdragon210_firehose.mbn> rl dump/   # 전체 파티션 리드
```

- 덤프에서 `system`/`super`/`boot` 추출 → `simg2img`/`binwalk`로 언팩. rootfs에서 **클로바 APK**, **CA 번들/피닝 자료** 위치 파악.
- 판정: read 성공 시 오프라인 분석·개조 가능. write까지 되면 system 개조 후 리플래시로 루팅 가능.

## 단계 5 — 루팅 ⬜

우선순위:
1. `fastboot oem unlock` 허용되면 → boot 이미지 Magisk 패치 → `fastboot flash boot` → Magisk 앱으로 root.
2. 구버전(2017 안드로이드) 커널/드라이버 **알려진 익스플로잇** 적용.
3. EDL write 가능 시 → system 이미지에 `su`/`adbd(root)`/내 앱을 **오프라인 주입** 후 리플래시.

루트 확보 후:
- **리퍼포즈(엔드스테이트 1)**: 클로바 앱 비활성(`pm disable`), 내 어시스턴트 APK 설치·부팅 자동실행.
- **앱 후킹(엔드스테이트 2)**: `frida-server`(기기 아키텍처=armeabi 확인) 푸시·실행 → 피닝 우회 스크립트 → `mitmproxy`로 CIC 관찰.

```bash
# 피닝 우회 후 트래픽 관찰(엔드스테이트 2)
frida -U -f <clova.package> -l frida-multiple-unpinning.js
mitmproxy --mode transparent   # + iptables 443 리다이렉트
```

## 판정 요약 (분기)

- 단계 2 성공 → 루팅/사이드로딩으로 직행, 최단.
- 단계 2 실패 → 3 → 4 순으로 발판 확보 후 루팅.
- 스냅드래곤 아님 → 단계 0에서 SoC별 대체 경로 재설계.

```bash
# adb/fastboot

git clone https://github.com/bkerler/edl && cd edl && pip install -r requirements.txt

pip install frida-tools mitmproxy
```
