# 비파괴 네트워크 경로 검토

## 질문
기기를 **열지 않고**, 가정용 공유기 단에서 **수 일간 트래픽을 모두 기록**하면 슈퍼클로바에 도움이 되는가?

## 짧은 답
**부분적으로 그렇다 — 단, "기록"만으로는 후킹이 안 된다.** 수동 캡처는 정찰이지 후킹이 아니다. TLS 암호화 때문에 내용(질문/응답/STT 텍스트)은 안 보이고 수정도 불가. 진짜 가치는 둘: (1) 엔드포인트·행동 지도, (2) **평문(비-TLS) 채널, 특히 안전하지 않은 OTA/펌웨어 업데이트 발견** — 이것이 유일한 비파괴 발판 후보다. 수 일 캡처는 (2)를 잡는 데 특히 유리하다(OTA 체크는 주기적이거나 드물게 발생하므로 긴 창이 필요).

## 수동 캡처로 얻는 것 / 못 얻는 것

**얻는 것**
- DNS 이름·목적지 IP·포트, TLS **SNI**(ClientHello의 서버명 — 2017년 기기라 ECH 미사용이라 보임)
- 트래픽 패턴·타이밍(음성/음악/텔레메트리 구분)
- **평문 엔드포인트**: 펌웨어/OTA 체크, 설정 fetch, 분석, NTP 등. 2017년경 저가 IoT는 일부 HTTP를 쓰는 경우가 흔함

**못 얻는 것**
- TLS 페이로드 **내용**(암호화) — 무슨 질문/응답인지 못 봄
- **수정·주입**(수동 캡처 = 읽기 전용)
- 사후 복호화(전방향 비밀성 때문에 나중에 키를 얻어도 불가)

→ "어디로 어떻게 말하는가"는 알아내지만 "무슨 말을 하는가"는 못 본다. 후킹의 **선행 정찰**.

## 비파괴로 실제 후킹하려면 — TLS 벽

능동 MITM(트래픽 리다이렉트 + 가짜 인증서)이 진짜 "외부 후킹"이다. 유일한 관문은 **기기가 내 CA를 신뢰하느냐**:

- **핸드셰이크 성공**(피닝/검증이 허술하거나 없음) → 비파괴로 CIC 평문 확보 → 백엔드 교체 가능. 사실상 승리.
- **핸드셰이크 실패**(제대로 검증) → 닫힌 기기에 내 CA를 심을 방법이 없으면 비파괴로는 막힘.
- 닫힌 기기에 CA를 **비파괴로** 심는 유일한 길 = 안전하지 않은 **OTA/설정 채널**(캡처로 발견) 또는 **LAN 서비스 취약점**.

즉 며칠 캡처의 전략적 목적은 명확하다: **"핀을 우회할 비파괴 구멍(평문 OTA·허술한 TLS·열린 LAN 서비스)이 있는가"를 찾는 것.**

## 현실적 판정

- **최선(며칠 확인 가치 충분):** 평문 HTTP OTA 또는 허술한 TLS 검증 존재 → **완전 비파괴 슈퍼클로바 가능.**
- **유력:** CIC가 핀/검증된 TLS + 평문 OTA 없음 → 비파괴 후킹은 벽 → 분해 경로가 신뢰 가능한 길.
- 어느 쪽이든 네트워크 정찰은 **싸고 안전하고 유익** → **먼저 한다.** 분해 경로의 표적(어떤 호스트를 사칭할지)도 여기서 나온다.

## 구체적 방법

### 캡처 세팅 (택1)
- **OpenWrt 공유기**면 라우터에서 직접 `tcpdump` — 가장 깔끔.
- **로그 AP**: 리눅스 박스에 hostapd로 AP를 세우고 스피커를 그 AP에 붙여 전량 캡처.
- **ARP 스푸핑**: 기존 LAN에서 `bettercap`으로 스피커 트래픽을 내 박스로 끌어옴(공유기 교체 불필요).
- **포트 미러링**: 관리형 스위치가 있으면 SPAN.

### 절차
1. 스피커 IP 확인(공유기 DHCP 테이블).
2. 수일 캡처(일 단위 로테이션):
   ```bash
   tcpdump -i <iface> host <speaker_ip> -w clova-%Y%m%d.pcap -G 86400
   ```
3. LAN 서비스 스캔(비파괴 발판 후보): `nmap -sV -p- <speaker_ip>`
4. 능동 TLS 벽 테스트(짧게, 비파괴 — 실패해도 일시적 먹통일 뿐 손상 없음):
   `bettercap` 또는 `mitmproxy --mode transparent`로 `*.clova.ai` 핸드셰이크 성공 여부 관찰.
5. 분석(Wireshark 필터):
   - `dns` — 어떤 호스트로 붙는지
   - `tls.handshake.type == 1` — SNI, TLS 버전·암호군(구식 TLS면 기회)
   - `http.request` — **평문 URL. `fw`/`ota`/`update`/`version`/`config` 포함 여부 집중**

### 판정 → 다음
- **평문 OTA/설정 발견** → 그걸 리다이렉트해 내 펌웨어/설정/CA 주입 시도(비파괴 발판 확보).
- **능동 MITM 핸드셰이크 성공** → CIC 평문 확보 → 백엔드 교체([경로분석.md](경로분석.md) 엔드스테이트 2).
- **둘 다 실패** → 비파괴 한계 확인 → [발판확보-런북.md](발판확보-런북.md) 분해 경로로.

## 참고
- 본인 소유 기기·본인 홈 네트워크 캡처라 사적 용도로 문제없음. 다만 캡처 파일엔 다른 트래픽도 섞일 수 있으니 스피커 IP로 필터링.
- 캡처만으로 "며칠간 무슨 말을 했는지"를 복원하는 건 **불가**(TLS). 그게 목적이라면 능동 MITM 또는 온디바이스 접근이 필요.
