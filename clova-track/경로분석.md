# 경로분석

## 원안: 세 경로

처음 도출한 세 가지 접근.

- **A. 네트워크 후킹 (CIC MITM).** 스피커 트래픽을 가로채 가짜 CIC 클라우드로 응답. "진짜 후킹". 관문은 TLS(인증서 검증/피닝)와 CIC 서버 구현.
- **B. 하드웨어 이식.** 통·마이크·스피커만 살리고 외장 보드(라즈베리파이 등)로 두뇌 교체. 확실하지만 별도 하드웨어 필요.
- **C. CEK 커스텀 확장.** 호출명으로 부르는 공식 스킬. 최소 노력이지만 반쪽짜리 + 콘솔 EOL.

## 재편: "기기 = 안드로이드" 가 A·B를 통합한다

기기가 안드로이드/스냅드래곤(→ [조사결과.md](조사결과.md) §3)이라는 사실이 판을 바꾼다.

- A의 TLS 관문 → **Frida 피닝 우회**로 해결(펌웨어 리플래시 불필요).
- B의 "외장 보드" → **불필요**. 기기 안에 이미 스냅210 안드로이드 두뇌 + 마이크 + 스피커가 있으니, 외장 라파 대신 **이 기기에 내 소프트웨어를 올리면** 된다.

즉 A와 B는 별개가 아니라, **하나의 "안드로이드 리버싱" 경로의 두 엔드스테이트**로 합쳐진다.

## 최종 경로

### ① 발판 확보 (공통 전제)

기기에서 코드 실행/펌웨어 접근 확보. 쉬운 문부터: `adb(USB)` → `UART 시리얼 콘솔` → `EDL 9008 덤프` → `루팅`. 상세는 [발판확보-런북.md](발판확보-런북.md).

### ② 엔드스테이트 — 두 갈래

**(1) 리퍼포즈 — 기기를 내 오픈 안드로이드 어시스턴트로 ⭐추천**
- 클로바 앱 정지 → 내 APK 탑재: 온디바이스 웨이크워드(openWakeWord/Porcupine) 또는 물리버튼 → 마이크 캡처 → STT → LLM → TTS → 기기 스피커.
- 한국어 품질: NCP CLOVA CSR/Voice 붙이거나 로컬 Whisper/Piper.
- **외장 하드웨어 불필요, 네이버 클라우드와 완전 무관.** 가장 확실·미래보장.
- 주의: 2017년 안드로이드(구버전)라 시스템 TLS·WebView가 낡음 → 앱 내부에서 최신 CA 번들/자체 트러스트스토어(OkHttp 등)로 현대 API 호출. 마이크/DSP는 ALSA/AudioRecord로 접근.

**(2) 앱 후킹 — 순정 UX("클로바야") 유지**
- 루팅 후 frida-server로 클로바 앱 피닝 우회 → CIC 트래픽 MITM → 내 STT/LLM/TTS를 CIC 포맷으로 응답. 또는 앱의 응답/TTS 함수를 직접 후킹해 답변 주입.
- 원래 웨이크워드·UX 보존이 장점, 작업량(CIC/앱 내부 분석)이 큼.

### C 폐기 근거

콘솔이 사실상 EOL이고, 설령 신규 등록이 가능해도 (i) 호출명으로 매번 불러야 하는 반쪽짜리, (ii) 네이버와 함께 죽는 시한부. 안드로이드 경로가 열린 이상 실익 없음.

## 비교

| 경로 | 노력 | 리스크 | 네이버 종료 후 생존 | UX | 결과물 |
|---|---|---|---|---|---|
| ①+②-1 리퍼포즈 | 중 (루팅+앱) | 중 (루팅 난이도) | ✅ 완전 독립 | 내 앱의 UX | 완전 자체 어시스턴트 |
| ①+②-2 앱 후킹 | 상 (CIC/앱 분석) | 중~상 | ✅ (백엔드 완전 대체 시) | 순정 "클로바야" | 순정 위 슈퍼클로바 |
| B 외장 라파 이식 | 중~상 (하드웨어) | 중 | ✅ | 내 UX | 몸통만 재활용 (열위) |
| C CEK 확장 | 하 | 낮음 | ❌ 함께 죽음 | 호출명 필요 | 반쪽짜리 (폐기) |

## 결정

**목표 = 엔드스테이트 (1) 리퍼포즈.** 순정 UX를 강하게 원하면 (2) 앱 후킹으로 선회. 둘 다 **① 발판 확보**가 선결이므로, 발판 난이도 판정을 먼저 한다(런북 참조). 발판 확보 결과에 따라 (1)/(2) 최종 확정.
