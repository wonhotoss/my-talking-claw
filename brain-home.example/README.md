# brain-home.example — 두뇌의 집 템플릿

day-10 설계(day-10.md): 두뇌 계층은 코드가 아니라 **관리자의 설정**이다. 이 디렉터리를
복사해 두뇌의 집으로 쓰고, 게이트웨이에 `AGENT_BRAIN=sdk BRAIN_HOME=<복사한 곳>`을 준다.
그 뒤로는 관리자가 그 디렉터리에서 `claude`를 열어 "말투를 바꿔", "가족 정보를 적어" 하면 된다.

```bash
cp -r brain-home.example ~/claw-home      # RPi: ~/claw-home이 이미 빈 workdir로 쓰이고 있었다
cd ~/claw-home && claude                  # 한 번 열어 "이 폴더를 신뢰합니까?"에 예 → 바로 종료해도 된다
```

**신뢰 수락은 필수다.** 신뢰되지 않은 폴더에서는 Claude Code가 `.claude/settings.json`의 `allow` 규칙을
**조용히 무시**한다(day-10 실기: "Ignoring 5 permissions.allow entries … this workspace has not been
trusted"). 그러면 두뇌가 `memory.md`도 `schedule/`도 못 쓰고 턴마다 사과만 한다. 게이트웨이는 기동
때 `~/.claude.json`의 `projects[<집>].hasTrustDialogAccepted`를 확인하고 없으면 **기동을 거부**한다.

**2026-11-12부터: `.claude/settings.json`만 관리자 전용, 나머지는 두뇌도 읽고 고친다**(사용자 결정, [뇌-상호작용-로드맵.md](../뇌-상호작용-로드맵.md) 3-1). 금지 대신 **기록**: 게이트웨이가 이 집을 git 저장소로 두고 기동 때·턴 끝·스케줄러 이동 때 바뀐 것을 커밋한다(`agent-gateway/app/home_history.py`).

| 파일 | 무엇 | 누가 고치나 | 언제 반영되나 |
| --- | --- | --- | --- |
| `CLAUDE.md` | **운영 규칙**: 무엇을 어디에 두는가, 말하는 규칙, 시간, 규칙을 고칠 때, 하지 않는 것 | 관리자, **두뇌** | **새 세션부터** (아래 "반영 시점") |
| `system.md` | **시스템 지도**: 기기·서비스·말 한 번의 경로, 할 수 있는 것/없는 것, 규칙의 층, 기록. 자동 포함 아님(두뇌가 필요할 때 Read) | 관리자, **두뇌** | 읽을 때 |
| `persona.md` | **성격·말투·이름·호칭** — `@persona.md`로 자동 포함. **이름은 관리자만**(=핫워드) | **두뇌(사용자가 말로)**, 관리자 | 두뇌가 고친 건 그 자리에서; 관리자가 고친 건 새 세션부터 |

| `.claude/settings.json` | 모델·권한 모드·허용/금지 도구 | **관리자만** (두뇌는 읽기만) | 게이트웨이 재시작 |

**반영 시점(실측, 2026-11-01).** CLAUDE.md와 그 `@import`(persona.md, memory.md)는 **세션 시작 때 한 번** 대화에 들어간다. 세션이 도는 중에 파일을 밖에서 고쳐도 다음 턴은 모른다(Read 도구를 뺀 세션에서 memory.md·CLAUDE.md를 고친 뒤 물어봐도 모름). 두뇌가 **스스로** 고친 건 그 턴의 도구 호출이 대화에 남으니 바로 따른다. 그래서:
- 사용자가 말로 바꾼 말투·기억 → 즉시. 다음 세션에도 파일로 남는다.
- 관리자가 손으로 고친 것 → 게이트웨이 재시작(세션은 `session.json`으로 이어진다; 시스템 프롬프트만 새 세션에 적용).

**관리자와 음성 사용자의 경계(사용자 결정).** 음성 사용자의 영역을 좁히지 않는다. 구현상 문제없는 것은 음성에도 연다 — 성격·말투·호칭·기억·예약, 그리고 2026-11-12부터 운영 규칙(`CLAUDE.md`)까지. 관리자는 초기 세팅과 도구 권한(`settings.json`), 그리고 **이름**을 쥐고, 두뇌의 부탁은 `requests.md`로 받는다.

**이름 = 핫워드(사용자 결정, 2026-11-13).** 기기를 깨우는 말이 곧 두뇌의 이름이다. 핫워드는 오디오 루프의 `WAKE_WORD_MODEL`(openWakeWord 기성 모델, `scripts/rpi-up.sh`)이라 두뇌가 바꿀 수 없으므로, 이름도 관리자가 둘을 함께 바꾼다: `persona.md`의 이름 줄 + `WAKE_WORD_MODEL` + 오디오 루프 재시작. 이 규칙은 `CLAUDE.md`에 적힌 무른 층이다.

## 단단한 층과 무른 층
- **단단한 층(호스트가 집행, 모델이 무시 못 함)**: `.claude/settings.json`의 모델·권한 모드·허용/금지 도구. `deny`에 적힌 도구는 정의 자체가 제거되고, `dontAsk`는 승인 요청을 거부로 바꾼다. 쓰기는 `Edit(/**)`(이 집 전체, `/`는 집 기준)로 열고 `Edit(/.claude/**)`를 거부한다 — Claude Code도 `.claude/`를 보호 경로로 다뤄 `dontAsk`에선 자기 도구의 쓰기를 거부하므로 이중이다. 집 밖 쓰기는 allow에 없어서 거부. 읽기(`Read`)는 전역. **이 층이 "절대"인 건 Bash가 닫혀 있는 동안이다** — Bash를 열면 같은 계정의 셸로 이 파일도 고칠 수 있고, 그때 지키는 건 git 기록이다.
- **무른 층(문서, 두뇌도 고친다)**: `CLAUDE.md`·`system.md`·`persona.md`·`memory.md`·`host.json`. `CLAUDE.md`에 쓴 금지는 두뇌가 `CLAUDE.md`를 고칠 수 있으므로 **권고**다. 정말 지킬 것은 `settings.json`으로.
- 어긋남은 **보인다**: 이 집의 모든 변경은 git 커밋(턴의 사용자 말이 이유로 붙는다), 도구 사용은 게이트웨이 로그의 `notice`.

## 세션을 미리 가르쳐 넘기기
이 디렉터리에서 `claude`를 대화형으로 열어 가르친 뒤, 그 세션 id를 `session.json`에
`{"session_id": "<uuid>"}`로 적으면 게이트웨이가 그 세션을 이어받는다(`/status`나
`claude --resume` 목록에서 id를 본다).
